TEST 1: INPUT TEXTBOX - BASIC TEXT ENTRY & VALUE EXTRACTION
───────────────────────────────────────────────────────────────────────────────

WHAT IT TESTS:
  • Locating input elements by ID
  • Verifying element visibility and enabled state
  • Getting HTML attributes (getAttribute)
  • Entering text with fill() action
  • Retrieving entered text with inputValue()

KEY METHODS DEMONSTRATED:
  • page.locator('#id') - Find element by ID
  • expect().toBeVisible() - Assert element visible
  • expect().toBeEnabled() - Assert element enabled
  • getAttribute('attribute') - Get HTML attribute value
  • fill('text') - Enter text into input field
  • inputValue() - Get the current value of input field

PRACTICAL CODE EXAMPLE:
  const nameInput = page.locator('#name');
  await expect(nameInput).toBeVisible();
  await expect(nameInput).toBeEnabled();
  const maxLen = await nameInput.getAttribute('maxlength');
  await nameInput.fill('John Doe');
  const value = await nameInput.inputValue();
  expect(value).toBe('John Doe');

WHEN TO USE:
  • Testing form field text input
  • Validating field attributes (maxlength, placeholder, required)
  • Filling out registration/login forms
  • Testing search inputs
  • Verifying user input is captured correctly

COMMON MISTAKES:
  ✗ Using textContent() instead of inputValue() on inputs
    → textContent() returns empty for input fields
  ✗ Not checking toBeVisible() before filling
    → May fail if element is hidden
  ✗ Using getAttribute() for value instead of inputValue()
    → getAttribute('value') gets initial value, not current value

  • expect().toBeChecked() - Assert radio is selected

MUTUAL EXCLUSIVITY CONCEPT:
  • Radio buttons with same name attribute form a group
  • Only ONE radio in group can be selected at a time
  • Selecting one automatically deselects the other
  • This is the KEY difference from checkboxes
  • HTML groups them with name="groupName"

TEST 7: SELECT DROPDOWN - SELECTION METHODS
───────────────────────────────────────────────────────────────────────────────

WHAT IT TESTS:
  • Selecting dropdown options with selectOption()
  • Getting selected value with inputValue()
  • Getting selected option label text (textContent)
  • Selecting by value attribute vs by displayed label
  • Understanding difference between option value and label

KEY METHODS DEMONSTRATED:
  • selectOption('value') - Select option by value attribute
  • selectOption({label: 'Text'}) - Select option by visible text
  • inputValue() - Get the VALUE attribute of selected option
  • textContent() - Get the LABEL text of selected option
  • locator('option:checked') - Query the selected option

PRACTICAL CODE EXAMPLE:
  const countrySelect = page.locator('#country');
  
  // Select by value
  await countrySelect.selectOption('in');
  const value = await countrySelect.inputValue();
  expect(value).toBe('in');
  
  // Get selected label
  const label = await countrySelect
    .locator('option:checked')
    .textContent();
  expect(label?.trim()).toBe('India');
  
  // Select by label
  await countrySelect.selectOption({label: 'United States'});

WHEN TO USE:
  • Testing country/region selection
  • Testing category selection
  • Testing dropdown filters
  • Testing size/color/option selection
  • Testing form submission with dropdowns

CRITICAL DISTINCTION:
  • selectOption('value') selects by VALUE attribute
  • selectOption({label: 'Text'}) selects by visible text
  • inputValue() returns the VALUE (not the label)
  • To get selected option's label: query option:checked then textContent()
  • This is a common source of confusion

TEST 8: inputValue() VS textContent() - DIRECT COMPARISON (CRITICAL)
───────────────────────────────────────────────────────────────────────────────

THIS IS THE MOST IMPORTANT TEST - PREVENTS COMMON FAILURES!

WHAT IT TESTS:
  • Demonstrates when to use inputValue() vs textContent()
  • Shows what happens when you use the WRONG method
  • Provides direct side-by-side comparison
  • Covers multiple element types

WHY THIS MATTERS:
  Using the wrong method is one of the top causes of test failures!
  Silent failures where tests get empty/null values instead of expected text.

COMPARISON 1: FORM INPUT (text)
────────────────────────────────
HTML: <input id="name" type="text" value="hello">

CORRECT METHOD: inputValue()
  const value = await nameInput.inputValue();
  // Returns: "hello" ✓

WRONG METHOD: textContent()
  const text = await nameInput.textContent();
  // Returns: "" (empty) ✗

COMPARISON 2: BUTTON ELEMENT
────────────────────────────
HTML: <button id="btn">Click Me</button>

WRONG METHOD: inputValue()
  const value = await button.inputValue();
  // Returns: null ✗ (not a form input)

CORRECT METHOD: textContent()
  const text = await button.textContent();
  // Returns: "Click Me" ✓

COMPARISON 3: SELECT DROPDOWN
─────────────────────────────
HTML: <select id="country">
        <option value="in">India</option>
        <option value="us">United States</option>
      </select>

For SELECTED OPTION VALUE:
  const value = await select.inputValue();
  // Returns: "in" ✓ (the value attribute)

For ALL OPTIONS TEXT:
  const allText = await select.textContent();
  // Returns: "India United States" (all option texts)

For SELECTED OPTION LABEL ONLY:
  const label = await select.locator('option:checked').textContent();
  // Returns: "India" ✓ (only selected option text)

QUICK REFERENCE TABLE
─────────────────────────────────────────────────────────────────────────────
Element Type           | To Get           | Use This           | Result
─────────────────────────────────────────────────────────────────────────────
<input type="text">    | Entered text     | inputValue()       | "text" ✓
<input type="text">    | Entered text     | textContent()      | "" ✗
<textarea>             | Text content     | inputValue()       | "text" ✓
<textarea>             | Text content     | textContent()      | "" ✗
<select>               | Selected value   | inputValue()       | "value" ✓
<select>               | All option text  | textContent()      | "opt1opt2..." ✓
<button>               | Button label     | textContent()      | "Click" ✓
<button>               | Button label     | inputValue()       | null ✗
<a href="...">Link</a> | Link text        | textContent()      | "Link" ✓
<div>Text</div>        | Div text         | textContent()      | "Text" ✓
<p>Paragraph</p>       | Paragraph text   | textContent()      | "Para..." ✓
─────────────────────────────────────────────────────────────────────────────

DECISION FLOWCHART
──────────────────

  Is it a FORM INPUT?
    (<input>, <textarea>, <select>)
    └─ YES → Use inputValue() ✓
    └─ NO → Use textContent() ✓

  Exception: For selected DROPDOWN OPTION label (not value)
    └─ Query option:checked then use textContent()

PRACTICAL TESTING EXAMPLE:

  // Test 1: Form input field
  const nameField = page.locator('#name');
  await nameField.fill('John');
  
  ✓ Correct:   expect(await nameField.inputValue()).toBe('John');
  ✗ Wrong:     expect(await nameField.textContent()).toBe('John');
              → Will fail: expects 'John' but got ''

  // Test 2: Button
  const submitBtn = page.locator('button[type="submit"]');
  
  ✓ Correct:   expect(await submitBtn.textContent()).toContain('Submit');
  ✗ Wrong:     expect(await submitBtn.inputValue()).toBe('Submit');
              → Will fail: expects 'Submit' but got null

  // Test 3: Dropdown
  const select = page.locator('#country');
  await select.selectOption('us');
  
  ✓ Correct (get value):  expect(await select.inputValue()).toBe('us');
  ✓ Correct (get label):  expect(await select
                            .locator('option:checked')
                            .textContent()).toContain('United States');
  ✗ Wrong:   expect(await select.textContent()).toBe('us');
            → Will fail: textContent() returns all option texts

SUMMARY
───────
  • inputValue() = Get the VALUE attribute of form inputs
  • textContent() = Get the displayed text of any element
  • Using wrong method = silent test failures
  • Check the quick reference table when uncertain

TEST 10: KEYBOARD ACTIONS - pressSequentially VS PRESS
───────────────────────────────────────────────────────────────────────────────

WHAT IT TESTS:
  • pressSequentially() for character-by-character typing
  • press() for specific keyboard keys
  • Keyboard shortcuts with modifiers
  • Difference between fill() and pressSequentially()

KEY METHODS DEMONSTRATED:
  • pressSequentially(text, {delay: ms}) - Type with character events
  • press(key) - Press specific key name
  • Key modifiers: 'Control+a', 'Shift+Tab', 'Meta+s', etc.

FILL() VS pressSequentially()
──────────────────────────────

fill() - Recommended for most cases
  • Fast typing simulation
  • Clears existing text first
  • Triggers single input event
  • Good for: Normal form filling
  • Speed: Very fast

  await field.fill('text');

pressSequentially() - For special handlers
  • Slow, character-by-character typing
  • Configurable delay between characters
  • Triggers keydown/keyup for each character
  • Good for: Autocomplete, validation, input handlers
  • Speed: Slow (but more realistic)

  await field.pressSequentially('text', {delay: 100});

PRACTICAL CODE EXAMPLES:

  // Basic typing with pressSequentially
  const searchInput = page.locator('#search');
  await searchInput.pressSequentially('React', {delay: 100});

  // Press Backspace
  await field.press('Backspace');

  // Press Enter (submit)
  await field.press('Enter');

  // Press Tab (move to next field)
  await field.press('Tab');

  // Keyboard shortcuts
  await field.press('Control+a');      // Select all
  await field.press('Control+c');      // Copy
  await field.press('Control+v');      // Paste
  await field.press('Control+z');      // Undo
  await field.press('Meta+s');         // Save (Mac)

  // Arrow keys
  await field.press('ArrowUp');
  await field.press('ArrowDown');
  await field.press('ArrowLeft');
  await field.press('ArrowRight');

WHEN TO USE pressSequentially():
  • Testing autocomplete handlers
  • Testing character-by-character validation
  • Testing input field event handlers
  • Testing real-time suggestions
  • Testing keyboard-specific behaviors

KEY PRESS NAMES:
  Special Keys: 'Enter', 'Escape', 'Backspace', 'Delete', 'Tab', 'Space'
  Navigation: 'ArrowUp', 'ArrowDown', 'ArrowLeft', 'ArrowRight'
  Page: 'PageUp', 'PageDown', 'Home', 'End'
  Character: 'a', 'A', '1', '@' (for single keys)
  Modifiers: 'Control+', 'Shift+', 'Alt+', 'Meta+'

TEST 13: SCROLL ACTIONS - SCROLLING
───────────────────────────────────────────────────────────────────────────────

WHAT IT TESTS:
  • Automatic scrolling (built into actions)
  • Explicit scrollIntoViewIfNeeded()
  • Manual page scrolling
  • Mouse wheel scrolling

KEY METHODS DEMONSTRATED:
  • scrollIntoViewIfNeeded() - Scroll element into viewport if needed
  • page.evaluate() - Custom scroll with JavaScript
  • page.mouse.wheel() - Mouse wheel scroll

PRACTICAL CODE EXAMPLES:

  // Automatic (built into fill, click, etc.)
  await field.fill('text'); // Auto-scrolls if needed

  // Explicit scroll
  await field.scrollIntoViewIfNeeded();

  // Scroll page with JavaScript
  await page.evaluate(() => window.scrollBy(0, 500)); // Scroll down 500px
  await page.evaluate(() => window.scrollTo(0, 1000)); // Scroll to position

  // Scroll element with JavaScript
  await page.evaluate(selector => {
    document.querySelector(selector).scrollIntoView();
  }, '#element-id');

  // Mouse wheel scroll
  await page.mouse.wheel(0, 500); // Scroll down

WHEN TO USE EXPLICIT SCROLLING:
  • Element is off-screen before action
  • Testing scroll-dependent behaviors
  • Testing lazy-loading
  • Testing infinite scroll
  • Testing scroll position

TESTING SCROLL BEHAVIOR PATTERN:

  test('lazy loaded content appears on scroll', async ({ page }) => {
    await page.goto('/');

    // Initially, item is not visible
    const item = page.locator('#lazy-loaded-item');
    let isVisible = await item.isVisible();
    expect(isVisible).toBe(false);

    // Scroll page to reveal item
    await page.evaluate(() => {
      document.querySelector('#lazy-loaded-item')
        .scrollIntoView();
    });

    // Now item is visible
    await expect(item).toBeVisible();
  });

KEY DIFFERENCE - scrollIntoViewIfNeeded():
  • "if needed" means it only scrolls if necessary
  • If element is already visible, no scroll happens
  • Efficient for performance
  • Built-in to most actions (fill, click, etc.)

TEST 14: FILE UPLOAD - setInputFiles
───────────────────────────────────────────────────────────────────────────────

WHAT IT TESTS:
  • Uploading single file using setInputFiles()
  • Uploading multiple files
  • Creating file buffer in memory
  • File input handling without dialog

KEY METHODS DEMONSTRATED:
  • setInputFiles(path) - Set file input with file path
  • setInputFiles([path1, path2]) - Multiple files
  • setInputFiles({name, mimeType, buffer}) - File buffer

PRACTICAL CODE EXAMPLES:

  // Single file upload from disk
  const fileInput = page.locator('input[type="file"]');
  await fileInput.setInputFiles('./documents/resume.pdf');

  // Multiple file upload
  await fileInput.setInputFiles([
    './documents/resume.pdf',
    './documents/cover-letter.pdf'
  ]);

  // File from memory buffer
  await fileInput.setInputFiles({
    name: 'test.txt',
    mimeType: 'text/plain',
    buffer: Buffer.from('Test file content')
  });

  // Multiple files with mixed sources
  await fileInput.setInputFiles([
    './real-file.pdf',
    {
      name: 'generated.txt',
      mimeType: 'text/plain',
      buffer: Buffer.from('Generated content')
    }
  ]);

  // Clear files
  await fileInput.setInputFiles([]);

WHY SETINPUTFILES() IS BETTER THAN DIALOG:
  • Much faster than file picker dialog
  • No flakiness from dialog handling
  • Works across all browsers reliably
  • Can create test files in memory
  • Doesn't require actual file on disk

WHEN TO USE:
  • Testing file upload forms
  • Testing document upload
  • Testing image upload
  • Testing batch file operations
  • Testing file validation

PRACTICAL SCENARIOS:

DECISION TREES

When to use which INPUT METHOD?
─────────────────────────────────
  Need to enter text in form field?
    └─ Just filling normal form?       → Use fill()
    └─ Testing autocomplete handler?   → Use pressSequentially()
    └─ Testing input validation?       → Use pressSequentially()

When to use which VALUE RETRIEVAL?
──────────────────────────────────────
  Need to get value from element?
    └─ Is it a form input?             → Use inputValue()
    └─ Is it another element?          → Use textContent()
    └─ Is it HTML attribute?           → Use getAttribute()
    └─ Is it selected dropdown label?  → Use textContent() on option:checked

When to use click() vs other methods?
──────────────────────────────────────
  Need to interact with element?
    └─ Click button/link?              → Use click()
    └─ Select checkbox/radio?          → Use check()/uncheck()
    └─ Select dropdown option?         → Use selectOption()
    └─ Type in text field?             → Use fill()
    └─ Trigger hover state?            → Use hover()

COMMON MISTAKES AND HOW TO FIX THEM
================================================================================

MISTAKE 1: Using textContent() on input field
──────────────────────────────────────────────
❌ WRONG:
  const value = await input.textContent();
  expect(value).toBe('test');  // FAILS: empty string

✅ CORRECT:
  const value = await inputValue();
  expect(value).toBe('test');

FIX: Use inputValue() for form inputs


MISTAKE 2: Using inputValue() on button
─────────────────────────────────────────
❌ WRONG:
  const text = await button.inputValue();
  expect(text).toBe('Click Me');  // FAILS: null

✅ CORRECT:
  const text = await button.textContent();
  expect(text).toContain('Click Me');

FIX: Use textContent() for non-form elements


MISTAKE 3: Not waiting for actionability
──────────────────────────────────────────
❌ WRONG:
  await page.goto('/');
  await button.click();  // May fail if not ready

✓ BETTER:
  await page.goto('/');
  await expect(button).toBeVisible();
  await expect(button).toBeEnabled();
  await button.click();

FIX: click() checks by default, but verify visibility first


MISTAKE 4: Using pressSequentially() when fill() is fine
──────────────────────────────────────────────────────────
❌ SLOW:
  await field.pressSequentially('test email text', {delay: 100});  // Very slow

✅ FAST:
  await field.fill('test email text');  // Much faster

FIX: Use fill() for normal form filling, pressSequentially() only when needed


MISTAKE 5: Not checking focus before testing focus behavior
─────────────────────────────────────────────────────────────
❌ INCOMPLETE:
  await field.focus();
  // No check if focus worked

✅ COMPLETE:
  await field.focus();
  const hasFocus = await field.evaluate((el) => 
    document.activeElement === el
  );
  expect(hasFocus).toBe(true);

FIX: Verify focus was set with evaluate()


MISTAKE 6: Forgetting drag needs source AND target
───────────────────────────────────────────────────
❌ WRONG:
  await item.dragTo();  // No target!

✅ CORRECT:
  const source = page.locator('#item');
  const target = page.locator('#zone');
  await source.dragTo(target);

FIX: Provide both source and target elements


MISTAKE 7: Using getAttribute('value') for current input value
──────────────────────────────────────────────────────────────
❌ WRONG:
  await field.fill('new value');
  const val = await field.getAttribute('value');
  // Gets initial value, not current value!

✅ CORRECT:
  await field.fill('new value');
  const val = await field.inputValue();
  // Gets current value

FIX: Use inputValue() for current value, getAttribute('value') for initial


MISTAKE 8: Not clearing input before testing new value
──────────────────────────────────────────────────────
❌ WRONG:
  await field.fill('first value');
  // ...later...
  await field.fill('second value');
  // fill() clears automatically, this is fine

✓ SAFE:
  // fill() always clears first, so this is safe
  await field.fill('new value');

FIX: fill() clears automatically, so just use it directly

KEY TAKEAWAYS
─────────────

1. fill() is the default method for entering text - use it 90% of the time
2. inputValue() is for form inputs ONLY (<input>, <textarea>, <select>)
3. textContent() is for ANY element (button, div, span, etc.)
4. click() automatically handles visibility and scrolling
5. focus() and blur() test form validation behaviors
6. hover() tests UI changes on mouse over
7. pressSequentially() is slower but tests keyboard handlers
8. setInputFiles() avoids flaky file picker dialogs
9. dragTo() simulates drag-and-drop interactions
10. getAttribute() validates HTML structure and attributes
