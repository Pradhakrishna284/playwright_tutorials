REQUEST-RESPONSE MATCHING BY ID
================================

Multiple requests in flight, responses out of order:

Request order:          Response order:        Matching:
   id:1 ──────────>        <──── id:3  ──> Matched by ID 3
   id:2 ──────────>        <──── id:1  ──> Matched by ID 1
   id:3 ──────────>        <──── id:2  ──> Matched by ID 2

Benefits:
  ├─ Responses can arrive out of order
  ├─ Allows true parallelization
  ├─ No need to wait for order
  └─ Efficient utilization of network

RETRY & RECOVERY
================

Transient Error (Network Hiccup):

    Attempt 1: FAIL (timeout)
        ↓ [Retry with backoff]
    Attempt 2: FAIL (connection reset)
        ↓ [Retry with backoff]
    Attempt 3: SUCCESS
        ↓
    Promise resolves
    Test continues

Playwright automatically handles retries for transient errors

test start
    │
    ├─ Launch browser
    │  └─ Browser process starts
    │  └─ Opens listening port (e.g., 52613)
    │
    ├─ Connect WebSocket
    │  └─ Playwright server → ws://localhost:52613/...
    │  └─ Handshake completes
    │  └─ Connected and ready
    │
    ├─ Create browser instance
    │  └─ Browser object created
    │  └─ Can now control browser
    │
    ├─ Run test code
    │  ├─ await page.goto(...)
    │  ├─ await page.click(...)
    │  ├─ await page.fill(...)
    │  └─ ... more operations ...
    │
    ├─ Close page/context
    │  └─ Clean up page resources
    │  └─ Close page connection
    │
    ├─ Close browser
    │  └─ Send close command via WebSocket
    │  └─ WebSocket connection closes
    │  └─ Browser process terminates
    │
    ▼
test end
