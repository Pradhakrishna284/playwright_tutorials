PLAYWRIGHT API TO CDP PROTOCOL TRANSLATION - COMPLETE EXAMPLES

HOW PLAYWRIGHT TRANSLATES YOUR CODE TO BROWSER COMMANDS

This document shows the transformation from high-level Playwright API calls
to low-level Chrome DevTools Protocol (CDP) messages that the browser understands.

================================================================================

EXAMPLE 1: PAGE NAVIGATION
===========================

YOUR CODE (What you write):
    await page.goto('https://demowebshop.tricentis.com/');

TRANSLATION PROCESS:
    1. Parse URL
    2. Validate URL format
    3. Create CDP protocol message
    4. Add request ID and parameters
    5. Serialize to JSON
    6. Send via WebSocket
    7. Wait for "Page.frameStoppedLoading" event
    8. Return promise

INTERNAL STEPS HIDDEN FROM YOU:
    ├─ Create navigation context
    ├─ Set HTTP headers
    ├─ Handle redirects
    ├─ Wait for network idle
    ├─ Parse response headers
    └─ Establish new connection if needed

CDP PROTOCOL MESSAGE SENT:
    {
        "id": 1,
        "method": "Page.navigate",
        "params": {
            "url": "https://demowebshop.tricentis.com/",
            "referrer": "",
            "transitionType": "typed"
        }
    }

BROWSER RESPONSE:
    {
        "id": 1,
        "result": {
            "frameId": "xxxxx-xxxxx-xxxxx"
        }
    }

EVENTS BROWSER SENDS (Unsolicited):
    [
        {
            "method": "Page.frameNavigated",
            "params": {
                "frame": {
                    "id": "xxxxx-xxxxx-xxxxx",
                    "mimeType": "text/html",
                    "securityOrigin": "https://demowebshop.tricentis.com",
                    "url": "https://demowebshop.tricentis.com/"
                }
            }
        },
        {
            "method": "Page.loadEventFired",
            "params": {
                "timestamp": 1234567890.123
            }
        },
        {
            "method": "Page.frameStoppedLoading",
            "params": {
                "frameId": "xxxxx-xxxxx-xxxxx"
            }
        }
    ]

YOUR CODE RESUMES:
    // goto completed
    // Next line executes


EXAMPLE 2: CLICKING AN ELEMENT
==============================

YOUR CODE (What you write):
    await page.click('//a[@class="product"]');

TRANSLATION PROCESS:
    Step 1: Parse XPath locator
            └─ '//a[@class="product"]'
    
    Step 2: Create XPath evaluation command (JavaScript)
            └─ Code to evaluate XPath in browser context
    
    Step 3: Send to browser (Runtime.evaluate)
            └─ Find element using XPath
    
    Step 4: Get element properties
            └─ Position, size, visibility status
    
    Step 5: Check if clickable
            └─ Is visible?
            └─ Is not disabled?
            └─ Is in viewport?
    
    Step 6: Calculate click coordinates
            └─ Center of element
    
    Step 7: Send mouse down command
    Step 8: Send mouse up command
    Step 9: Send click event
    
    Step 10: Wait for any side effects
             └─ Navigation? Wait for load event
             └─ Modal dialog? Wait for dialog
    
    Step 11: Return success to test code

CDP MESSAGES SENT (Step-by-step):

Message 1: Evaluate XPath to find element
    {
        "id": 42,
        "method": "Runtime.evaluate",
        "params": {
            "expression": "document.evaluate('//a[@class=\"product\"]', document, null, XPathResult.FIRST_ORDERED_NODE_TYPE, null).singleNodeValue",
            "returnByValue": false,
            "generatePreview": true
        }
    }

Browser Response:
    {
        "id": 42,
        "result": {
            "type": "object",
            "objectId": "element-12345",
            "className": "HTMLAnchorElement",
            "description": "<a class=\"product\">..."
        }
    }

Message 2: Get element bounding box
    {
        "id": 43,
        "method": "DOM.getBoxModel",
        "params": {
            "objectId": "element-12345"
        }
    }

Browser Response:
    {
        "id": 43,
        "result": {
            "model": {
                "content": [100, 50, 250, 50, 250, 100, 100, 100],
                "padding": [95, 45, 255, 105],
                "border": [90, 40, 260, 110],
                "margin": [85, 35, 265, 115],
                "width": 150,
                "height": 50
            }
        }
    }

Message 3: Scroll into view if needed
    {
        "id": 44,
        "method": "Runtime.callFunctionOn",
        "params": {
            "functionDeclaration": "function() { return this.scrollIntoView(true); }",
            "objectId": "element-12345"
        }
    }

Message 4: Dispatch mouse down
    {
        "id": 45,
        "method": "Input.dispatchMouseEvent",
        "params": {
            "type": "mousePressed",
            "x": 175,
            "y": 75,
            "button": "left",
            "clickCount": 1,
            "modifiers": 0
        }
    }

Message 5: Dispatch mouse up
    {
        "id": 46,
        "method": "Input.dispatchMouseEvent",
        "params": {
            "type": "mouseReleased",
            "x": 175,
            "y": 75,
            "button": "left",
            "clickCount": 1,
            "modifiers": 0
        }
    }

Message 6: Dispatch click event
    {
        "id": 47,
        "method": "Input.dispatchMouseEvent",
        "params": {
            "type": "mousePressed",
            "x": 175,
            "y": 75,
            "button": "left",
            "clickCount": 1
        }
    }

Events Browser Sends (If click causes navigation):
    {
        "method": "Page.frameNavigated",
        "params": { "frame": {...} }
    }

EXAMPLE 5: WAIT FOR ELEMENT
===========================

YOUR CODE (What you write):
    await page.waitForSelector('.success-message', {timeout: 5000});

TRANSLATION PROCESS:
    Step 1: Parse selector '.success-message'
    Step 2: Set timeout to 5000ms
    Step 3: Start polling (or use mutation observer)
    Step 4: Execute querySelector in browser repeatedly
    Step 5: Check if element exists and is visible
    Step 6: Either resolve (success) or reject (timeout)

CDP MESSAGES SENT (Polling approach):

First attempt (T=0ms):
    {
        "id": 200,
        "method": "Runtime.evaluate",
        "params": {
            "expression": "document.querySelector('.success-message')",
            "returnByValue": false
        }
    }

Response (Not found):
    { "id": 200, "result": { "value": null } }

Second attempt (T=100ms):
    {
        "id": 201,
        "method": "Runtime.evaluate",
        "params": {
            "expression": "document.querySelector('.success-message')"
        }
    }

... polling continues until found or timeout ...

Success (T=450ms):
    {
        "id": 220,
        "result": {
            "type": "object",
            "objectId": "element-success"
        }
    }

Promise resolves and test continues

EXAMPLE 11: INTERCEPT & ABORT REQUESTS
======================================

YOUR CODE (What you write):
    await page.route('**/*.png', route => route.abort());
    await page.goto('https://example.com');

TRANSLATION PROCESS:
    Step 1: Set up request route matcher
    Step 2: Navigate to page
    Step 3: Browser makes requests
    Step 4: Server intercepts matching requests
    Step 5: Server calls abort()
    Step 6: Request is blocked

CDP MESSAGES:

Enable request interception:
    {
        "id": 700,
        "method": "Fetch.enable",
        "params": {
            "patterns": [
                {
                    "urlPattern": "*.png",
                    "requestStage": "HeadersReceived"
                }
            ]
        }
    }

Browser sends intercepted request event:
    {
        "method": "Fetch.requestPaused",
        "params": {
            "requestId": "request-123",
            "request": {
                "url": "https://example.com/image.png",
                "method": "GET",
                "headers": {...}
            }
        }
    }

Abort the request:
    {
        "id": 701,
        "method": "Fetch.failRequest",
        "params": {
            "requestId": "request-123",
            "errorReason": "BlockedByClient"
        }
    }

Browser Response:
    { "id": 701, "result": {} }

IMPORTANT PATTERNS
==================

1. FINDING ELEMENTS
   ├─ Always uses Runtime.evaluate
   ├─ Browser executes querySelector/XPath
   ├─ Returns element object reference
   └─ Multiple methods: CSS, XPath, text, role

2. CHECKING PROPERTIES
   ├─ Uses DOM.getBoxModel for positions
   ├─ Uses Runtime.evaluate for visibility
   ├─ Uses Runtime.evaluate for text content
   └─ Checks happen before actions

3. SENDING INPUT
   ├─ Each key press = 2 messages (down + up)
   ├─ Each character requires separate messages
   ├─ Mouse movement sends continuous updates
   ├─ Modifiers (Shift, Ctrl) are flags

4. WAITING FOR EVENTS
   ├─ Browser sends unsolicited events
   ├─ Server forwards events to test code
   ├─ Promises resolve when events fire
   └─ Timeouts prevent infinite wait

5. INTERCEPTION
   ├─ Server acts as proxy for requests
   ├─ Can abort, modify, or mock responses
   ├─ Transparent to page JavaScript
   └─ Useful for testing error scenarios

6. ASSERTIONS
   ├─ Find element
   ├─ Get expected property
   ├─ Compare with actual value
   ├─ Report pass/fail to test


PERFORMANCE IMPLICATIONS
========================

High-overhead operations:
    ├─ Filling long text (1 message per character)
    ├─ Multiple consecutive operations (wait between)
    ├─ Polling (waitForSelector repeats query)
    └─ Network interception (adds latency)

Optimized patterns:
    ├─ Use parallel operations (Promise.all)
    ├─ Use specific selectors (avoid scanning DOM)
    ├─ Use built-in waits (less polling)
    └─ Batch updates (reduce round-trips)
