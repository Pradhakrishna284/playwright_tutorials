SECTION 1: ACTIONS INTRODUCTION & CORE CONCEPTS
================================================================================

WHAT ARE ACTIONS IN PLAYWRIGHT?

Actions are methods that simulate real user interactions with HTML elements.
Playwright provides a comprehensive API to interact with:
  • Text inputs (text, email, password, date, time fields)
  • Checkboxes and radio buttons
  • Select dropdowns
  • Buttons (single, double, right-click)
  • Keyboard keys and shortcuts
  • File uploads
  • Form focus
  • Drag and drop operations
  • Scrolling

WHY USE PLAYWRIGHT ACTIONS?

Traditional approach (DOM manipulation):
  ✗ Doesn't reflect actual user behavior
  ✗ Doesn't trigger all events (focus, blur, input, change)
  ✗ Doesn't work with dynamically hidden elements
  ✗ Ignores JavaScript event listeners
  ✗ Breaks on page animations

Playwright actions approach:
  ✓ Simulates real user interactions
  ✓ Triggers all relevant browser events
  ✓ Waits for elements to be actionable
  ✓ Automatically scrolls elements into view
  ✓ Handles dynamic content gracefully
  ✓ Works across Chromium, Firefox, WebKit

ACTION SAFETY FEATURES (Built-in Actionability Checks)

Before any action, Playwright automatically:

1. ELEMENT STABILITY
   └─ Waits for element to be in DOM
   └─ Waits for display (not hidden)
   └─ Waits for non-zero dimensions

2. VISIBILITY
   └─ Waits for visibility:hidden to be false
   └─ Waits for display:none to be false
   └─ Waits for opacity > 0

3. MOTION
   └─ Waits for CSS transitions to complete
   └─ Waits for animations to finish
   └─ Waits for element to stop moving

4. POSITIONING
   └─ Scrolls element into view automatically
   └─ Positions element in viewport

5. INTERACTIVITY
   └─ Waits for pointer events (not obscured)
   └─ Waits for element to be enabled
   └─ Waits for no overlay elements

6. RESILIENCE
   └─ Auto-retries if element detaches
   └─ Handles dynamic DOM changes
   └─ Waits for JavaScript to settle

ACTION TIMEOUT

Default: 30 seconds per action
Configurable at:
  • Test level: test.setTimeout(60000)
  • Global level: timeout in playwright.config.ts
  • Action level: await locator.click({ timeout: 5000 })

CRITICAL CONCEPT: inputValue() vs textContent - WHEN TO USE WHICH
================================================================================

Two methods to extract text/values from elements. UNDERSTAND THE DIFFERENCE.

┌─────────────────────────────────────────────────────────────────────────────┐
│                           QUICK COMPARISON                                 │
├──────────────────┬──────────────────────┬──────────────────────────────────┤
│ Feature          │ inputValue()         │ textContent()                    │
├──────────────────┼──────────────────────┼──────────────────────────────────┤
│ Works on         │ Form inputs only     │ ANY element                      │
│ Element types    │ <input>, <textarea>, │ <button>, <div>, <span>,        │
│                  │ <select>             │ <a>, <p>, etc.                  │
│ Returns          │ VALUE attribute      │ All text content                │
│ Return type      │ string | null        │ string | null                   │
│ Use case         │ Form field values    │ Button text, labels, messages   │
│ Hidden content   │ Returns value anyway │ Includes hidden text            │
│ Whitespace       │ Preserved            │ Included and normalized         │
└──────────────────┴──────────────────────┴──────────────────────────────────┘

CRITICAL EXAMPLES - These Show The ACTUAL Difference

EXAMPLE 1: Simple Text Input
─────────────────────────────
HTML:
  <input type="text" id="email" value="user@example.com" placeholder="Enter email">

CODE:
  const input = page.locator('#email');
  const inputVal = await input.inputValue();      // "user@example.com"
  const textContent = await input.textContent();  // ""

RESULT:
  inputValue()  → "user@example.com"  ✓ Correct - this is the VALUE
  textContent   → ""                  ✗ Empty - inputs have no text content

WHEN TO USE:
  Use inputValue() for input fields ✓

EXAMPLE 2: Password Input
──────────────────────────
HTML:
  <input type="password" id="pass" value="secret123">

CODE:
  const input = page.locator('#pass');
  const inputVal = await input.inputValue();      // "secret123"
  const textContent = await input.textContent();  // ""

RESULT:
  inputValue()  → "secret123"         ✓ Returns the actual value (not masked)
  textContent   → ""                  ✗ Empty - inputs have no text

UI DISPLAY: ••••••••  (masked to user, but value is stored plaintext in HTML)

WHEN TO USE:
  Use inputValue() for password fields ✓

EXAMPLE 3: Textarea
────────────────────
HTML:
  <textarea id="comments">My feedback\nLine 2\nLine 3</textarea>

CODE:
  const textarea = page.locator('#comments');
  const inputVal = await textarea.inputValue();      // "My feedback\nLine 2\nLine 3"
  const textContent = await textarea.textContent();  // "My feedback\nLine 2\nLine 3"

RESULT:
  inputValue()  → "My feedback\nLine 2\nLine 3"  ✓ Correct
  textContent   → "My feedback\nLine 2\nLine 3"  ✓ Also works for textarea

WHEN TO USE:
  Use inputValue() for textarea (standard for form inputs) ✓
  textContent also works but inputValue() is the standard

EXAMPLE 4: Select Dropdown
────────────────────────────
HTML:
  <select id="country">
    <option value="us">United States</option>
    <option value="ca" selected>Canada</option>
  </select>

CODE:
  const select = page.locator('#country');
  const inputVal = await select.inputValue();      // "ca"
  const textContent = await select.textContent();  // "United States\nCanada"

RESULT:
  inputValue()  → "ca"                       ✓ Selected option VALUE
  textContent   → "United States\nCanada"    ✗ All option text, not selected

WHEN TO USE:
  Use inputValue() to get the selected value ✓

EXAMPLE 5: Button Element
──────────────────────────
HTML:
  <button id="submit">Click Me Now</button>

CODE:
  const button = page.locator('#submit');
  const inputVal = await button.inputValue();      // null
  const textContent = await button.textContent();  // "Click Me Now"

RESULT:
  inputValue()  → null                ✗ Buttons are not form inputs
  textContent   → "Click Me Now"      ✓ Correct - button's displayed text

WHEN TO USE:
  Use textContent() for buttons ✓

EXAMPLE 6: Link (Anchor)
────────────────────────
HTML:
  <a href="/login" id="login-link">Sign In</a>

CODE:
  const link = page.locator('#login-link');
  const inputVal = await link.inputValue();      // null
  const textContent = await link.textContent();  // "Sign In"

RESULT:
  inputValue()  → null        ✗ Links are not form inputs
  textContent   → "Sign In"   ✓ Correct - link's displayed text

WHEN TO USE:
  Use textContent() for links ✓

EXAMPLE 7: Div Container
────────────────────────
HTML:
  <div id="message" class="success">Order Confirmed! Your ID is #12345</div>

CODE:
  const div = page.locator('#message');
  const inputVal = await div.inputValue();      // null
  const textContent = await div.textContent();  // "Order Confirmed! Your ID is #12345"

RESULT:
  inputValue()  → null                                  ✗ Not a form input
  textContent   → "Order Confirmed! Your ID is #12345" ✓ Correct

WHEN TO USE:
  Use textContent() for divs, message containers ✓

EXAMPLE 8: Span with Hidden Text
─────────────────────────────────
HTML:
  <span id="status">
    Status: <span style="display:none">processing</span> Complete
  </span>

CODE:
  const span = page.locator('#status');
  const inputVal = await span.inputValue();      // null
  const textContent = await span.textContent();  // "Status: processing Complete"

RESULT:
  inputValue()  → null                        ✗ Not a form input
  textContent   → "Status: processing Complete" ✓ Includes hidden text too

WHEN TO USE:
  Use textContent() - but note it includes hidden text

DECISION TREE: Which One to Use?
─────────────────────────────────

START: I need to get text/value from an element

Q1: Is it a form input? (<input>, <textarea>, <select>)
    YES → Use inputValue()
    NO  → Go to Q2

Q2: Is it any other element? (button, div, span, link, etc.)
    YES → Use textContent()
    MAYBE → Try inputValue() first, fall back to textContent()

SIMPLE RULE:
  • Form inputs? → inputValue()
  • Anything else? → textContent()
  • Unsure? → inputValue() returns null for non-inputs, try that first

COMMON MISTAKES

MISTAKE 1: Using textContent on input field
────────────────────────────────────────────
❌ WRONG:
const email = page.locator('#email');
const value = await email.textContent();  // Returns ""
expect(value).toBe('user@example.com');    // Fails! textContent is empty

✓ CORRECT:
const email = page.locator('#email');
const value = await email.inputValue();   // Returns "user@example.com"
expect(value).toBe('user@example.com');    // Passes!

MISTAKE 2: Using inputValue on button
──────────────────────────────────────
❌ WRONG:
const button = page.locator('button');
const text = await button.inputValue();  // Returns null
expect(text).toBe('Submit');              // Fails! inputValue is null

✓ CORRECT:
const button = page.locator('button');
const text = await button.textContent();  // Returns "Submit"
expect(text).toBe('Submit');              // Passes!

MISTAKE 3: Using inputValue on select to get label
──────────────────────────────────────────────────
❌ WRONG (if you want the label):
const select = page.locator('#country');
await select.selectOption('ca');
const label = await select.inputValue();  // Returns "ca" (the VALUE)
expect(label).toBe('Canada');             // Fails! Returns "ca" not "Canada"

✓ CORRECT (if you want the VALUE):
const select = page.locator('#country');
await select.selectOption('ca');
const value = await select.inputValue();  // Returns "ca" (the VALUE)
expect(value).toBe('ca');                 // Passes!

✓ CORRECT (if you want the LABEL):
const select = page.locator('#country');
const selectedOption = select.locator('option:checked');
const label = await selectedOption.textContent();  // Returns "Canada"
expect(label).toBe('Canada');  // Passes!

THE fill() METHOD

Purpose: Fill text input fields with text
Best for: Normal text entry (use this 90% of the time)
Advantages: Simple, fast, event-complete

Syntax:
  await locator.fill(value, options?)

Parameters:
  • value (string): Text to fill into the field
  • options.timeout: Maximum time to wait (default: 30000ms)
  • options.noWaitAfter: Skip waiting for navigation (rare)
  • options.force: Bypass actionability checks (not recommended)

What fill() Does Internally:
  1. Finds the element matching locator
  2. Waits for actionability
  3. Focuses the element
  4. Clears existing text
  5. Types the new text
  6. Triggers input event
  7. Waits for change handlers

Example 1: Simple Text Input
────────────────────────────
import { test, expect } from '@playwright/test';

test('fill text input', async ({ page }) => {
  await page.goto('https://demowebshop.tricentis.com');
  
  // By role (most reliable)
  await page.getByRole('textbox', { name: 'Search' }).fill('shoes');
  
  // By label
  await page.getByLabel('Product Name').fill('Running Shoes');
  
  // By placeholder
  await page.getByPlaceholder('Enter your name').fill('John Doe');
  
  // By test id
  await page.getByTestId('search-input').fill('laptop');
  
  // Using locator selectors
  await page.locator('#search-field').fill('tablet');
  await page.locator('[name="username"]').fill('admin@example.com');
});

Example 2: Different Input Types
──────────────────────────────────

Common Error Scenarios:
──────────────────────

Error: "element is not visible"
Cause: Element is hidden, not in viewport, or display:none
Fix: 
  • Check CSS visibility properties
  • Verify element is in DOM
  • Scroll element into view first

Error: "element is covered by another element"
Cause: Modal, overlay, or another element on top
Fix:
  • Use { force: true } (not recommended)
  • Close the covering element
  • Wait for element to become visible

Error: "timeout waiting for element to be stable"
Cause: Animations or continuously moving element
Fix:
  • Increase timeout: await locator.fill(text, { timeout: 10000 })
  • Wait for animation to finish
  • Wait for element stability

THE setChecked() / check() / uncheck() METHODS

Purpose: Toggle checkboxes and radio buttons
Syntax:
  await locator.check()           // Check (radio/checkbox)
  await locator.uncheck()         // Uncheck (checkbox only)
  await locator.setChecked(true)  // Set checked state
  await locator.setChecked(false) // Uncheck

Supported Elements:
  • <input type="checkbox">
  • <input type="radio">
  • Elements with [role="checkbox"]

What check() Does:
  1. Waits for actionability
  2. Checks if already checked
  3. If not checked, clicks to check
  4. Waits for input/change events

Example 1: Simple Checkbox
────────────────────────────
test('checkbox operations', async ({ page }) => {
  await page.goto('https://example.com/form');
  
  // Check a checkbox
  await page.getByLabel('I agree to terms').check();
  
  // Verify it's checked
  await expect(page.getByLabel('I agree to terms')).toBeChecked();
  
  // Uncheck a checkbox
  await page.getByLabel('Subscribe to newsletter').uncheck();
  
  // Verify it's unchecked
  await expect(page.getByLabel('Subscribe to newsletter')).not.toBeChecked();
  
  // Using setChecked for dynamic control
  await page.getByLabel('Remember me').setChecked(true);
});

Example 2: Multiple Checkboxes
────────────────────────────────
test('multiple checkboxes', async ({ page }) => {
  await page.goto('https://example.com/preferences');
  
  // Check multiple items
  await page.getByLabel('Email Notifications').check();
  await page.getByLabel('SMS Notifications').check();
  await page.getByLabel('Push Notifications').check();
  
  // Uncheck all
  const preferences = page.locator('input[type="checkbox"]');
  const count = await preferences.count();
  for (let i = 0; i < count; i++) {
    await preferences.nth(i).uncheck();
  }
  
  // Check only specific ones by filter
  const notificationCheckboxes = page.locator(
    'input[type="checkbox"]:has-text("notification")'
  );
  await notificationCheckboxes.check();
});

Example 3: Radio Buttons
──────────────────────────
test('radio button operations', async ({ page }) => {
  await page.goto('https://example.com/options');
  
  // Select a radio button option
  await page.getByLabel('Small').check();
  
  // Verify selection
  await expect(page.getByLabel('Small')).toBeChecked();
  
  // Switch selection (previous unchecks automatically)
  await page.getByLabel('Large').check();
  
  // Verify new selection
  await expect(page.getByLabel('Large')).toBeChecked();
  await expect(page.getByLabel('Small')).not.toBeChecked();
  
  // Get selected value
  const selected = await page.locator(
    'input[type="radio"]:checked'
  ).inputValue();
  expect(selected).toBe('large');
});

Example 4: Role-based Checkboxes
─────────────────────────────────
test('checkbox with role attribute', async ({ page }) => {
  await page.goto('https://example.com/accessible');
  
  // Checkboxes using role="checkbox"
  await page.getByRole('checkbox', { name: 'Accept Terms' }).check();
  
  // Verify accessibility
  await expect(
    page.getByRole('checkbox', { name: 'Accept Terms' })
  ).toBeChecked();
});

Assertion Methods for Checkboxes:

// Enable/Disable

SECTION 4: SELECT DROPDOWN ACTIONS

THE selectOption() METHOD

Purpose: Select options from <select> dropdown menus
Syntax:
  await locator.selectOption(values, options?)

Parameters:
  • values: String | string[] | SelectOption | SelectOption[]
  • SelectOption: { value?: string, label?: string, index?: number }

Supported Elements:
  • <select> elements
  • <select multiple>

Selection Methods:
  1. By value: selectOption('red')
  2. By label: selectOption({ label: 'Red Color' })
  3. By index: selectOption({ index: 0 })
  4. Multiple: selectOption(['red', 'green', 'blue'])

Example 1: Single Selection
────────────────────────────
test('select single option', async ({ page }) => {
  await page.goto('https://example.com/form');
  
  // Select by value
  await page.getByLabel('Country').selectOption('US');
  
  // Select by label
  await page.getByLabel('Color').selectOption({ label: 'Blue' });
  
  // Select by index (0-based)
  await page.getByLabel('Priority').selectOption({ index: 1 });
  
  // Verify selection
  await expect(page.locator('select')).toHaveValue('US');
});

Example 2: Multiple Selection - Basic Patterns
────────────────────────────────────────────────
test('select multiple options by value', async ({ page }) => {
  await page.goto('https://example.com/form');
  
  // Select multiple colors (MUST have <select multiple> attribute)
  await page.getByLabel('Choose Colors').selectOption([
    'red',
    'green',
    'blue'
  ]);
  
  // Verify selections using toHaveValues
  await expect(page.getByLabel('Choose Colors')).toHaveValues([
    'red',
    'green',
    'blue'
  ]);
});

test('select multiple options by label', async ({ page }) => {
  await page.goto('https://example.com/form');
  
  // Select by labels
  await page.getByLabel('Interests').selectOption([
    { label: 'Sports' },
    { label: 'Music' },
    { label: 'Reading' }
  ]);
  
  // Verify using evaluate for more control
  const selectedLabels = await page.getByLabel('Interests').evaluate(() => {
    const selected = document.querySelectorAll('option:checked');
    return Array.from(selected).map((option: any) => option.label);
  });
  expect(selectedLabels).toEqual(['Sports', 'Music', 'Reading']);
});

test('select multiple options by index', async ({ page }) => {
  await page.goto('https://example.com/form');
  
  // Select first 3 options by index (0-based)
  const multiSelect = page.locator('select[multiple]');
  await multiSelect.selectOption([
    { index: 0 },
    { index: 1 },
    { index: 2 }
  ]);
  
  // Verify selections
  const selectedCount = await multiSelect.evaluate(() => 
    document.querySelectorAll('option:checked').length
  );
  expect(selectedCount).toBe(3);
});

test('mixed selection methods', async ({ page }) => {
  // Mix value, label, and index in same selectOption call
  const multiSelect = page.locator('#colors');
  
  await multiSelect.selectOption([
    'red',                          // by value
    { label: 'Green' },             // by label
    { index: 4 }                    // by index
  ]);
  
  const selectedCount = await multiSelect.evaluate(() => 
    document.querySelectorAll('option:checked').length
  );
  expect(selectedCount).toBe(3);
});

Example 3: Advanced Multi-Select Operations
────────────────────────────────────────────
test('clear and reselect patterns', async ({ page }) => {
  const multiSelect = page.getByLabel('Select Items');
  
  // Select initial items
  await multiSelect.selectOption(['item1', 'item2', 'item3']);
  await expect(multiSelect).toHaveValues(['item1', 'item2', 'item3']);
  
  // Clear all selections by passing empty array
  await multiSelect.selectOption([]);
  
  // Verify all cleared
  const remaining = await multiSelect.evaluate(() => 
    document.querySelectorAll('option:checked').length
  );
  expect(remaining).toBe(0);
  
  // Re-select new items
  await multiSelect.selectOption(['item2', 'item4']);
  await expect(multiSelect).toHaveValues(['item2', 'item4']);
});

test('select all available options', async ({ page }) => {
  const multiSelect = page.locator('#colors');
  
  // Get all option values
  const allOptions = await multiSelect.locator('option').evaluate(
    elements => elements.map((el: any) => el.value)
  );
  
  console.log('All available options:', allOptions);
  
  // Select all
  await multiSelect.selectOption(allOptions);
  
  // Verify all selected
  const selectedCount = await multiSelect.evaluate(() => 
    document.querySelectorAll('option:checked').length
  );
  expect(selectedCount).toBe(allOptions.length);
});

test('get all option information', async ({ page }) => {
  const multiSelect = page.locator('#colors');
  
  // Get count of all options
  const optionsCount = await multiSelect.locator('option').count();
  console.log(`Total options: ${optionsCount}`);
  
  // Get all option texts
  const allOptionTexts = await multiSelect.locator('option')
    .allTextContents();
  console.log('Option labels:', allOptionTexts);
  
  // Get all option values
  const allOptionValues = await multiSelect.locator('option').evaluate(
    elements => elements.map((el: any) => el.value)
  );

MULTI-SELECT BEST PRACTICES
─────────────────────────────
1. ALWAYS check for 'multiple' attribute before selecting multiple values
2. ALWAYS wait for dynamically loaded options before selecting
3. USE evaluate() for complex verification instead of just toHaveValues()
4. USE allTextContents() to verify available options before selection
5. HANDLE empty selections with selectOption([]) to clear everything
6. VERIFY selection count with evaluate() for edge case testing
7. DESELECT individual items by passing all-except-that-item array

COMMON ERRORS
──────────────
Error: "Cannot select multiple on non-multiple select"
Cause: selectOption(['val1', 'val2']) on <select> without multiple attribute
Fix: Verify HTML has <select multiple> or only select one value

Error: "locator did not resolve to any elements"
Cause: Select element not in DOM when selection attempted
Fix: Add explicit wait or waitForSelector before selectOption()

Error: Verification fails with toHaveValues()
Cause: Order mismatch or unexpected values selected
Fix: Use evaluate() to get actual values and inspect them

Issue: "Multi-select shows only non-selected options after first action"
Cause: CTRL+Click behavior not simulated by selectOption()
Fix: selectOption() handles multiple correctly - verify HTML structure

SCROLLING METHODS

Playwright auto-scrolls for most actions, but sometimes you need manual control.

Methods:
  1. scrollIntoViewIfNeeded()   - Scroll element into view
  2. mouse.wheel()             - Scroll with wheel
  3. page.evaluate()           - Programmatic scroll
  4. page.keyboard.press()     - Keyboard scroll

Example 1: Auto-scroll (Default Behavior)
──────────────────────────────────────────
test('auto scroll on click', async ({ page }) => {
  await page.goto('https://example.com/long-page');
  
  // Playwright automatically scrolls before action
  // No need to do anything special
  await page.getByText('Footer Button').click();
  
  // The button is automatically scrolled into view
  // Then clicked
});

Example 2: scrollIntoViewIfNeeded()
────────────────────────────────────
test('scroll element into view', async ({ page }) => {
  await page.goto('https://example.com/long-page');
  
  // Explicitly scroll element into view
  const footer = page.getByText('Footer Content');
  await footer.scrollIntoViewIfNeeded();
  
  // Now perform action
  await footer.click();
  
  // Use when:
  // • Testing scroll behavior separately
  // • Infinite lists need scrolling to load more
  // • Need element visible before taking screenshot
});

Example 3: Mouse Wheel Scroll
───────────────────────────────
test('scroll with mouse wheel', async ({ page }) => {
  await page.goto('https://example.com/page');
  
  // Scroll down
  await page.mouse.wheel(0, 10);     // y: positive = down
  
  // Scroll up
  await page.mouse.wheel(0, -10);    // y: negative = up
  
  // Horizontal scroll
  await page.mouse.wheel(10, 0);     // x: positive = right
  
  // Multiple scrolls
  for (let i = 0; i < 5; i++) {
    await page.mouse.wheel(0, 5);    // Scroll down gradually
  }
});

Example 4: Programmatic Scroll
────────────────────────────────
test('programmatic scroll', async ({ page }) => {
  await page.goto('https://example.com/page');
  
  // Scroll entire page
  await page.evaluate(() => {
    window.scrollBy(0, 500);  // Scroll down 500px
  });
  
  // Scroll specific element
  await page.locator('[data-testid="scrollable-div"]').evaluate(el => {
    el.scrollTop += 300;
  });
  
  // Scroll to top
  await page.evaluate(() => {
    window.scrollTo(0, 0);
  });
  
  // Scroll to bottom
  await page.evaluate(() => {
    window.scrollTo(0, document.body.scrollHeight);
  });
});

Pattern 1: Action with Event Verification
────────────────────────────────────────────
test('verify input event fired', async ({ page }) => {
  await page.goto('https://example.com/form');
  
  // Listen for input event
  let eventFired = false;

    });
  });
  
  // Fill triggers input event
  await page.getByLabel('Username').fill('testuser');
  
  // Verify via UI change (not direct variable)

test('conditional click', async ({ page }) => {

  const button = page.getByRole('button', { name: 'Delete' });
  
  if (await button.isVisible()) {
    await button.click();
    await expect(page.getByText('Deleted')).toBeVisible();
  }
});

Pattern 3: Action Retry Logic
───────────────────────────────
test('action with retry', async ({ page }) => {
  const retryAction = async (action, maxRetries = 3) => {
    for (let i = 0; i < maxRetries; i++) {
      try {
        await action();
        break;
      } catch (error) {
        if (i === maxRetries - 1) throw error;
        await page.waitForTimeout(1000);
      }
    }
  };
  
  await retryAction(
    () => page.getByRole('button').click()
  );
});

Pattern 4: Multi-Action Sequence
──────────────────────────────────
test('action sequence', async ({ page }) => {
  const form = page.getByRole('form');
  
  // Type username
  await form.getByLabel('Username').fill('testuser');
  
  // Type password
  await form.getByLabel('Password').fill('password123');
  
  // Check remember me
  await form.getByLabel('Remember me').check();
  
  // Select country
  await form.getByLabel('Country').selectOption('USA');
  
  // Click submit
  await form.getByRole('button', { name: 'Login' }).click();
});

Pattern 5: Wait for Action to Settle
──────────────────────────────────────
test('action with network wait', async ({ page }) => {
  await page.goto('https://example.com');
  
  // Wait for navigation after click
  await Promise.all([
    page.waitForNavigation(),
    page.getByRole('link', { name: 'Next' }).click()
  ]);
  
  // Wait for response after submit
  const responsePromise = page.waitForResponse(
    response => response.url().includes('/api/save')
  );
  
  await page.getByRole('button', { name: 'Save' }).click();

  expect(response.ok()).toBe(true);

SECTION 13: BEST PRACTICES & TROUBLESHOOTING
================================================================================

BEST PRACTICES

1. Prefer fill() over pressSequentially()
   ✓ GOOD:  await input.fill('text');
   ✗ BAD:   await input.pressSequentially('text');
   Reason: fill() is faster and sufficient for most cases

2. Use proper locators
   ✓ GOOD:  await page.getByLabel('Email').fill('user@example.com');
   ✗ BAD:   await page.locator('#email-field-div-2-input').fill(...);
   Reason: Locators are more robust to DOM changes

3. Avoid force: true
   ✓ GOOD:  await locator.click();
   ✗ BAD:   await locator.click({ force: true });
   Reason: force bypasses actionability checks

4. Don't use evaluate for interactions
   ✓ GOOD:  await button.click();
   ✗ BAD:   await page.evaluate(() => 
              document.querySelector('button').click()
            );
   Reason: evaluate doesn't simulate real events

5. Wait for network, not timeouts
   ✓ GOOD:  await Promise.all([
              page.waitForNavigation(),
              button.click()
            ]);
   ✗ BAD:   await button.click();
             await page.waitForTimeout(2000);
   Reason: Network-based waiting is deterministic

6. Check actionability separately
   ✓ GOOD:  await expect(button).toBeEnabled();
             await button.click();
   ✗ BAD:   try { await button.click(); } catch(e) {}
   Reason: Explicit checks improve readability

7. Use accessible locators
   ✓ GOOD:  getByRole, getByLabel, getByPlaceholder
   ✗ BAD:   locator('.btn-primary'), locator('#id-123')
   Reason: More stable and accessibility-friendly

8. Separate concerns
   ✓ GOOD:  // Login helper
             async function login(page, email, password) {
               await page.getByLabel('Email').fill(email);
               await page.getByLabel('Password').fill(password);
               await page.getByRole('button', { name: 'Login' }).click();
             }
   ✗ BAD:   // All logic in test
             test('...', async ({ page }) => { ... });

COMMON TROUBLESHOOTING

Issue: "Timeout waiting for element to be visible"
─────────────────────────────────────────────────
Causes:
  • Element doesn't exist
  • Element is hidden (display:none, visibility:hidden)
  • Element is outside viewport
  • JavaScript is still loading

Solutions:
  1. Verify selector: await page.getByLabel('Email').count() > 0
  2. Check visibility: await page.getByLabel('Email').isVisible()
  3. Increase timeout: { timeout: 60000 }
  4. Wait for page load: await page.waitForLoadState('networkidle')

Issue: "Element is covered by other element"
──────────────────────────────────────────────
Causes:
  • Modal dialog on top
  • Sticky header covering element
  • Tooltip or overlay
  • Floating button

Solutions:
  1. Close the covering element first
  2. Scroll to ensure clear view
  3. Use { force: true } only as last resort
  4. Adjust timing/wait for animations

Issue: "Click did not trigger expected action"
────────────────────────────────────────────────
Causes:
  • Event listeners not registered
  • JavaScript not fully loaded
  • Wrong locator selected element

Solutions:
  1. Verify correct element: await locator.screenshot()
  2. Check event listeners: 
     await page.evaluate(() => {
       const el = document.querySelector('button');
       return el._getEventListeners?.('click')?.length || 0;
     });
  3. Wait for network: await page.waitForLoadState('networkidle')

Issue: "File upload fails silently"
────────────────────────────────────
Causes:
  • File path doesn't exist
  • Wrong selector for file input
  • File input inside form that auto-submits

Solutions:
  1. Verify file exists: 
     const fs = require('fs');
     expect(fs.existsSync(filepath)).toBe(true);
  2. Verify file input element:
     await expect(page.locator('input[type="file"]')).toBeAttached();
  3. Debug with console:
     await page.getByLabel('Upload').setInputFiles(filepath);
     console.log('Files set');

Performance Tips:

1. Parallel actions (when independent):
   await Promise.all([
     page.getByLabel('Email').fill('user@example.com'),
     page.getByLabel('Name').fill('John Doe')
   ]);

2. Batch operations:
   const selects = page.locator('select');
   for (let i = 0; i < await selects.count(); i++) {
     await selects.nth(i).selectOption('option1');
   }

3. Avoid unnecessary waits:
   ✗ BAD:   await page.waitForTimeout(2000);
   ✓ GOOD:  await page.waitForNavigation();

4. Use test.describe.serial() for dependent tests:
   test.describe.serial('Workflow', () => {
     // Tests run sequentially
   });
