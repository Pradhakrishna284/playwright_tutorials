ULTRA-SIMPLE INTERVIEW ANSWERS
(30-60 seconds each - no fluff)

================================================================================
Q1: WHAT IS PLAYWRIGHT?
================================================================================

ANSWER (30 seconds):
"Playwright is a test automation framework that controls browsers via 
Chrome DevTools Protocol. It's fast, reliable, and supports Chromium, 
Firefox, and WebKit. I use it to write end-to-end tests."


================================================================================
Q2: HOW DOES IT WORK?
================================================================================

ANSWER (60 seconds):
"Playwright has layers:
  1. I write: await page.click('#button')
  2. API layer: converts to command
  3. Protocol layer: creates CDP message
  4. WebSocket: sends to browser
  5. Browser: performs action
  6. Promise resolves, test continues"


================================================================================
Q3: WHY WORKERS?
================================================================================

ANSWER (45 seconds):
"Tests run in parallel. On a 6-core machine, 6 workers run simultaneously.
  • 17 tests with 1 worker: 17 minutes
  • 17 tests with 6 workers: 3 minutes
  
Each worker has own browser instance, no interference."


================================================================================
Q4: WHAT IS ISOLATION?
================================================================================

ANSWER (30 seconds):
"Each test runs in isolated browser context:
  • Own cookies (cleared after test)
  • Own local storage (cleared after test)
  • Own DOM
  
Tests can't affect each other."


================================================================================
Q5: HOW DO YOU FIND ELEMENTS?
================================================================================

ANSWER (30 seconds):
"Locator engine supports:
  • CSS: page.locator('.button')
  • XPath: page.locator('//button')
  • Text: page.locator('text=Click me')
  • Role: page.locator('[role=\"button\"]')
  • TestID: page.locator('[data-testid=\"btn\"]')"


================================================================================
Q6: WHAT'S CDP?
================================================================================

ANSWER (30 seconds):
"Chrome DevTools Protocol - JSON messages over WebSocket.

Request (us→browser):
  {\"method\": \"Page.navigate\", \"params\": {\"url\": \"...\"}}

Response (browser→us):
  {\"result\": {\"frameId\": \"123\"}}

That's how Playwright talks to browser."


================================================================================
Q7: WHAT ABOUT ASYNC?
================================================================================

ANSWER (30 seconds):
"Everything returns Promises. Use async/await:

  await page.goto(url);      // Wait for page load
  await page.click('#btn');  // Wait for click
  
Waits for browser response, then continues."


================================================================================
Q8: HOW DO YOU HANDLE ERRORS?
================================================================================

ANSWER (45 seconds):
"Use try/catch:

  try {
    await page.click('#button');
  } catch(e) {
    console.log('Click failed:', e);
  }

Or assertions:
  await expect(page.locator('#btn')).toBeVisible();
  
Test fails if assertion false."


================================================================================
Q9: WHAT'S A FIXTURE?
================================================================================

ANSWER (30 seconds):
"Reusable setup/teardown. Example:

  test.extend({
    userContext: async ({page}, use) => {
      await loginUser(page);        // Setup
      await use(page);              // Test uses it
      await logoutUser(page);       // Cleanup
    }
  });"


================================================================================
Q10: PARALLEL vs SEQUENTIAL?
================================================================================

ANSWER (30 seconds):
"Parallel (default):
  workers: undefined    // Auto-detect: 6 on 6-core machine
  
Sequential (CI):
  workers: 1            // One worker, no parallelization

Configure in playwright.config.ts"


================================================================================
Q11: WHY PLAYWRIGHT vs SELENIUM?
================================================================================

ANSWER (45 seconds):
"Playwright:
  ✓ Direct CDP protocol (faster)
  ✓ Built-in async/await
  ✓ Auto-waiting for elements
  ✓ Same code for all browsers
  ✓ Multi-browser in one session

Selenium:
  ✗ HTTP server overhead (slower)
  ✗ Manual waits needed
  ✗ Different for each browser"


================================================================================
Q12: WHAT HAPPENS IF BROWSER CRASHES?
================================================================================

ANSWER (30 seconds):
"Worker detects crash, marks test FAILED, continues with other workers.
Test context recorded (logs, screenshots). Testing continues with 
remaining workers."


================================================================================
Q13: HOW DO YOU DEBUG?
================================================================================

ANSWER (45 seconds):
"Three ways:
  1. Inspector: npx playwright codegen (records test)
  2. Trace: trace: 'on' in config (records everything)
  3. Headless false: see browser running
  4. Debug: npx playwright test --debug (step through)"


================================================================================
Q14: WHAT'S A SELECTOR?
================================================================================

ANSWER (30 seconds):
"Way to find elements:
  • CSS: #id, .class, button
  • XPath: //tag, //*[@attr='val']
  • Playwright prefers simpler: text, role, testid

Good selector: specific, stable, readable"


================================================================================
Q15: HOW FAST IS IT?
================================================================================

ANSWER (30 seconds):
"With 6 parallel workers:
  • Per test: 1-3 seconds typical
  • 17 tests: 3 minutes (parallel)
  • Same 17 tests: 30 minutes (sequential)
  
Speed depends on: app speed, network, browser load time"


================================================================================
COMMON FOLLOW-UP QUESTIONS
================================================================================

"HOW DO YOU HANDLE FLAKY TESTS?"
→ "Auto-retries, proper waiting (not Thread.sleep), 
   assert on actual conditions, increase timeouts for slow apps"

"WHAT'S YOUR TIMEOUT?"
→ "Default 30 seconds. I increase for slow operations, 
   decrease for quick checks"

"HOW DO YOU TEST MOBILE?"
→ "Use devices: 'Pixel 5' in config, tests same code, 
   different viewport"

"HOW DO YOU LOGIN USERS?"
→ "beforeEach hook with authentication, or use 
   stored auth tokens to skip login"

"HOW DO YOU HANDLE POPUPS?"
→ "page.on('popup', popup => {...}) listens for popups,
   then interact with popup page"

"HOW DO YOU DO NETWORK STUBBING?"
→ "page.route() intercepts requests, can mock or modify"

"WHAT'S YOUR BEST PRACTICE?"
→ "Use data-testid for selection, avoid flaky waits,
   organize tests logically, use fixtures for setup"

EXAMPLE FULL INTERVIEW
================================================================================

Q: "Explain Playwright architecture"

A: "Playwright is layered. You write test code that calls the API layer. 
   That converts to Chrome DevTools Protocol messages. Sent to browser 
   via WebSocket. Browser executes, sends back result. Promise resolves.
   
   Main benefit: each layer can be optimized. Users write simple code, 
   protocol handles complexity."

(~60 seconds, covered: what it is, how it works, why it's designed that way)

INTERVIEWER: "How many workers?"

A: "Depends on CPU cores. On a 6-core machine, it defaults to 6 workers. 
   Each worker = independent browser instance. Tests run parallel.
   
   Trade-off: more workers = faster, but more memory used."

(~40 seconds, covered: what happens, why it works, trade-off)

INTERVIEWER: "Can one test affect another?"

A: "No. Each worker has isolated browser context. Cookies cleared after 
   each test. Storage cleared. Completely isolated."

(~20 seconds, direct answer)
