01

Core Architecture — Browser · Context · Page

Your TypeScript test script connects to a real browser process via a persistent WebSocket (CDP for Chromium, patched protocols for Firefox/WebKit). The Browser spawns isolated BrowserContexts (think incognito windows), each holding one or more Pages (tabs). Every locator action on a Page is routed through the auto-wait engine before touching the DOM.

02

Single Test Run Lifecycle (Login Test Example)

What actually happens from the moment npx playwright test is invoked until the test result is recorded and the context torn down — using a typical login flow as the example.

03

Auto-Wait — Actionability Checks

Before every action (click, fill, check…), Playwright runs a sequence of checks. If any check fails, it silently retries the whole sequence until the element satisfies all conditions or the timeout is reached — eliminating almost all manual wait/sleep calls.

04

Page Object Model & Fixtures

Tests request a custom fixture (loggedInPage) by name. Playwright runs the fixture's setup code (which internally uses the LoginPage POM to navigate and log in), then calls use(page) to hand the ready page to the test. After the test body finishes, any teardown code in the fixture runs automatically.

05

Authentication & Storage State Reuse

Log in once via a dedicated setup project, save the cookies/localStorage to user.json, then every subsequent test context loads that file and starts already authenticated — no repeated UI login per test.

06

Network Interception & Routing

Register page.route(pattern, handler) before any matching request fires. Playwright intercepts the request and lets you choose: mock a response entirely (fulfill), pass it through with optional modifications (continue), or kill it (abort).
